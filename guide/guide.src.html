Changing content

Edit one place, the whole site updates

All text, offices, people and projects live in one block called CONTENT near the top of the site's script. Change a value there and every page that uses it updates.

  1. Open the site file

    Open index.html in a code editor and search for const CONTENT.

  2. Find the section you need

    offices for addresses and emails, leadership for names and photos, projects for case studies, journey for the timeline, privacy for the policy text.

  3. Change the text between the quotes

    Keep the quotes and commas. For example, to add a phone number: phones: ["+65 9778 4324"].

  4. Check it, then publish

    Open the file in a browser, click through the page you changed, then upload it (see Publishing).

Adding photos: put the image in the photo or img field as a file path such as /assets/team.webp. Pages without a photo show a blueprint drawing instead.

Publishing

Putting it live

  1. Turn on normal web addresses

    Add <script>window.SITE_ROUTER = "path"</script> before the site scripts, so pages use /design-services/ instead of #design-services.

  2. Upload the deploy pack

    Upload index.html, sitemap.xml, robots.txt, the .well-known folder and either vercel.json (Vercel) or .htaccess (Apache).

  3. Connect the contact form

    Set window.SITE_FORM_ENDPOINT to your form service address (https only), and add that domain to the security policy.

  4. Tell Google

    Submit https://21-knots.com/sitemap.xml in Google Search Console.

Security

How the site stays safe

No login, no databaseNothing for attackers to break into on the site itself.
Security headersStrict content policy, HTTPS only, no framing, no MIME sniffing.
Spam-resistant formHidden trap field, time check, one message per 30 seconds.
Old WordPress retiredLogin and XML-RPC addresses blocked once the new site is live.

Full details are in SECURITY-AUDIT.md in the deploy pack. Re-check yearly at securityheaders.com and renew the date in security.txt.
